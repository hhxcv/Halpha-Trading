# Halpha 文档验证方法

按修改含义选择以下检查。普通文案关注原意和引用；行为或边界变化再检查受影响语义、所有权和关键反例。不需逐条回填清单或为无关项记录“不适用”。

## 语义检查

- 用户结果、资金边界、动作、事实、停止、接管和结束含义没有被意外改变。
- 每项稳定语义只有一个所有者；相邻文档只保留本地消费和失败结果。
- 未知没有被写成失败、零值或安全状态。
- Demo 与 Live 的身份、凭据、动作和结果仍隔离。
- 当前没有消费者的对象、状态、流程、证据和治理概念已经删除。

## 层级检查

- L0 只有使命、最高边界和取舍。
- L1 没有字段、完整状态机、供应商、当前实施或建设顺序。
- L2 没有精确字段、当前组件和相邻领域完整流程。
- L3 没有当前工作、精确版本、当前实例和实际结果。
- L4 有时间、范围和来源，不创造稳定规则。
- L0–L4 没有开发阶段、建设包、阶段顺序或阶段完成状态；L4 只记录当前焦点和事实。

## 复杂度检查

- 规范只有一份中文正文，没有通过翻译、流程副本、登记或索引建立另一份权威；直接链接与任务内比较不需维护第二份规范。
- 没有为了校验器而创建第二份事实或流程。
- 代码、配置、锁文件和 Git 已拥有的详细事实没有在 L4 全量复制。
- 精确进程数、记录族数、页面数和组件接线只有确实构成长期行为时才进入 L3，否则留在 L4或代码。
- 普通 Git、直接测试和人工决定足够时，没有新增治理机制。

## 机械检查

使用仓库可用 Python 环境，从根目录检查修改路径：

```powershell
python .agents/skills/write-halpha-docs/scripts/validate_halpha_docs.py <修改路径...>
python governance/validate_current_plan.py  # 修改 L4 时
```

机械校验只检查 UTF-8、YAML、文件名、最小元数据、相对链接和少量层级禁词。通过不表示语义正确。

文档规则或多处引用关系变化时扩大到相关文档集合。完成适用检查后，仅因新增修改、失败或尚未解决的疑点重跑；纯文档修改不自动触发产品完整测试。已存在的其他工作区问题按实际来源区分。

## 交付

先说明修改是否满足目标，再给实际验证与剩余未知。发现语义、层级或所有权错误时，指出条款和实际影响。结论使用普通语言即可，不建立固定评审状态，也不以文档数量、篇幅或检查数量证明质量。
