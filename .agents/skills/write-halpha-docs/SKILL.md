# Halpha 文档工作

## 目标与入口

产品语义由当前 `docs/L0`–`docs/L4` 中文正文拥有，文档结构由 `HALPHA-DOC-001` 拥有；授权、隐私和工作区边界见 `AGENTS.md`。本技能提供编辑方法，不另建产品规则或审批。

按本次问题读取参考中的相关部分：

| 问题 | 参考 |
|---|---|
| 放置层级、唯一所有者、文件元数据、拆分或去重 | [文档规则](references/documentation-rules.md) |
| 行为、责任、失败、组件或维护复杂度变化 | [设计要求](references/design-requirements.md) |
| 修改收尾或语义评审 | [验证方法](references/validation.md) |

文案与链接修正读取目标段落及上下文即可。语义变更读取拥有者的完整相关契约和会受影响的直接上下游；总体方向、资金边界或跨域所有权变更再读相关上位全文。只有当前范围、选择或结果会影响决定时才读取对应 L4；同一任务中已读取且未变化的内容无需反复加载。

## 编辑判断

- 定位要改变的含义及其唯一所有者，修改拥有者和真正失真的直接引用。先清除本次范围内的重复、无消费者概念和过时要求，避免顺手重整无关领域。
- 用用户结果、允许行为、责任、失败与结束说明契约。章节、表格和篇幅随内容选择，普通说明不必填满模板或逐项声明“不适用”。
- 用户已经授权的目标和必要修订可连续完成，常规措辞、结构和方法选择自主处理。仅当仍缺少会实质改变目标、业务含义或权限的决定时请求澄清，不以 L0/L1/L2 标签自动要求再次审批。
- 区分应当实现的规则、已读到的实现和已验证的事实。代码可揭示设计错误，也可支持有范围的实现结论；不能据此推断未观察的外部状态或自动改写 L4。
- L4 更新须在授权内并有当前来源、时间和范围；没有记录或证据不足时保持未知，不从旧 Git 修订补齐。稳定语义变更不自动产生 L4 事实变化。
- 动作唯一、防重复、事实核对、保护、停止与接管属于产品正确性；评审次数、材料格式和流程强度按实际影响选择。

## 复核与交付

检查差异及相关上下文是否保留原意、唯一所有者和直接消费关系。核心交易含义、资金边界或跨域变化要从正常路径和关键反例复核；独立视角用于高失败成本或难以消除的歧义，不规定固定人数或固定轮数。

执行 [验证方法](references/validation.md) 中适用的机械检查。报告实际修改、证据、剩余未知和影响；无需新增评审状态、配套记录或固定格式的结论标签。
