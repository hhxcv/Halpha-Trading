# UX Review Checklist

Use only sections affected by the change; this is a review aid, not a form to complete. A critical semantic or control defect cannot be offset by visual polish.

## Scope and Trading Value

- The changed surface serves an authorized user job, with a clear domain owner for facts and commands.
- Sample data and assumptions are distinguishable from implemented and observed behavior.
- Layout keeps applicable environment, exposure, protection, open responsibility, unknown state and available controls visible.
- Comparable numbers preserve units, precision, sign and time meaning under the current UX contract.
- Presentation choices improve repeated expert use or necessary recovery without adding unjustified routes or concepts.

## Visual Structure and Disclosure

- Current theme and component states are consistent; affected focus, contrast and numeric alignment remain legible.
- Secondary explanation can unfold without hiding critical facts, failures or controls.
- Disclosure and dialogs preserve task context, keyboard access and focus return where applicable.
- A substantial redesign or unresolved pattern uses relevant current first-party evidence; one direct precedent may suffice. No benchmark matrix or “not applicable” record is required by default.
- Images, when produced, have been inspected at intended size.

## Feedback and Consequential Actions

- Changed controls give immediate feedback and distinguish request acknowledgement from authoritative outcome.
- Applicable pending, rejected, failed, stale and unknown results remain understandable and actionable.
- Work surviving refresh or navigation can be found through its owning result; only necessary identity and progress are added.
- Changed consequential actions have the preview and explicit user action required by their domain owner. No extra authorization object or generic approval layer was invented.
- Affected duplicate, retry, interruption and stale-preview paths preserve the same responsibility and permissions.
- Stop, exit and takeover remain reachable; unknown results are not displayed as safe or complete.

## Browser and Accessibility Evidence

- Executable visual or interaction changes have been inspected under [Browser Validation](playwright-visual-validation.md) at relevant states and widths.
- Affected keyboard operation, accessible names, focus, contrast, zoom and responsive layout were checked where the change could alter them.
- Relevant runtime errors or failed requests were investigated; evidence distinguishes application defects from unavailable dependencies.
- The handoff states actual outcomes and limits. Static artifacts are not described as interaction-validated.

## Decisions and Handoff

Layout, scan order, component polish and disclosure can be chosen autonomously within the authorized result and current product meaning. Adding a route to carry an already authorized job does not by itself create a new approval requirement.

If a material user job, authority, risk behavior, support boundary or externally consequential action remains undecided, provide the smallest concrete decision and use `write-halpha-docs` for authorized semantic changes. Do not reconfirm the explicit task or decisions already fixed in current design. Report the result and material limits without a mandatory inventory or approval sequence.
