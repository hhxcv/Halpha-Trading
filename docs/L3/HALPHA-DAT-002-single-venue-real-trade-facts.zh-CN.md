# Halpha 场所交易事实契约

**文档编号：** HALPHA-DAT-002  
**层级：** L3  
**L3 类型：** DOMAIN  
**主要语义所有者：** DAT  
**所属实现模块：** venue_integration 的事实分区  
**语言版本：** zh-CN  
**上位文档或条款：** HALPHA-DAT-001  
**直接依赖：** 无  
**直接消费者：** HALPHA-ALP-002、HALPHA-TRADEPLAN-002、HALPHA-CAP-002、HALPHA-EXE-002、HALPHA-OUT-002  
**适用纵向约束：** HALPHA-SYS-001、HALPHA-ENG-001  
**本文档负责：** 场所事实记录、来源映射、归属、未知、修正和组件边界  
**本文档不负责：** 策略、计划、资金、动作决定和当前场所、账户、阈值

## 1. 设计结论

Halpha 使用一个追加式场所事实结构保存当前消费者实际引用的市场、工具、账户、订单、成交、费用、资金费、持仓和保护事实。未被产品决定使用的行情留在量化组件内；仅供图表观察的当前环境行情不写入场所事实结构，也不建设全量行情仓库或第二事实源。

## 2. 最小事实结构

每条事实包含稳定事实身份、环境与场所、按用途适用的账户和工具、来源和外部对象身份、来源时间、取得时间、事实截止点、规范内容摘要、业务载荷，以及必要的激活/动作归属或修正引用。

资本数值使用确定精度并保存单位和来源精度。相同来源对象和内容幂等；同一外部身份出现不同内容时追加变化并在冲突解决前返回未知。

当前支持的事实种类由产品代码和 L4 记录，不在本契约固定数量。

## 3. 来源与归属

场所查询和带稳定身份的公开事件可以形成事实。组件缓存、组合、风险投影和合成事件只能帮助寻找或比较，不能单独证明场所受理、实际费用、持仓归零或责任闭合。

订单、成交和费用只有在稳定外部身份、环境、账户、工具和条款都匹配同一已持久动作时才归属 Halpha。用户接管和其他外部活动保持外部身份，不能补造成 Halpha 动作或精确策略收益。

保证金模式不参与订单或盈亏归属。全仓与逐仓都只按同一激活的稳定动作身份归集成交和费用；账户权益变化、账户总盈亏、其他激活或外部交易不得按比例分摊给某个策略。

交易所资金费只提供账户、工具和事件时间的合并金额时，DAT 先保存该账户资金费事实，再按事件时点每个激活由唯一成交事实推导的同向绝对虚拟持仓分摊。分摊使用交易所金额精度的确定性最大余数法，逐激活分摊合计必须严格等于原账户金额，并引用原资金费事实、事件时点、各激活持仓和方法；方向冲突、持仓为零但金额非零、成交时间未知或合计无法核对时不分摊并保持未知。这是资金费这一缺少动作身份的账户事实的窄派生规则，不允许把账户权益、总盈亏或其他费用按比例分配。

账户持仓事实不归属单个动作。每个激活的虚拟持仓由该激活唯一 `ENTRY` 成交有符号累加，再扣除该激活保护、止盈、减仓和退出成交确定性推导，不另建可人工更新的持仓账本。消费者把交易所账户持仓用于自动减仓、退出或闭合时，必须重新校验环境、场所、账户、工具、权威查询来源、取得时间与截止点，并同时证明目标激活虚拟持仓、同范围全部激活虚拟持仓合计和交易所净仓一致。其他账户、其他工具、流式估计、过期查询或未解决外部活动不能因数值相同而替代。

私有只读账户观察可以把同一查询窗口内的完整账户权益摘要、账户持仓、普通开放订单和条件或算法开放订单保存为账户级事实，供 CAP 检查新增风险纪律，并供工作台显示账户权益、外部仓位和接管资格。权益摘要只保存交易所明确返回的钱包余额、未实现盈亏、保证金余额、可用余额、初始保证金、维持保证金及其组成，不从仓位或订单自行推算。该事实必须标明只读、完整性、账户身份、查询范围、取得时间和统一截止点；只保存非零仓位的展示载荷不表示未查询其他工具。查询类别任一失败时整次快照不成立，不持久化半快照。旧格式快照可以继续支持其原有只读展示，但缺少权益摘要时不能支持账户级新增风险纪律。工作台可以把没有任何 Halpha 激活归属证据的仓位标为“外部未管理”；同工具存在 Halpha 归属时只能显示账户总仓与需要核对，不得把净仓全部标成外部或全部归给 Halpha。

外部仓位接管前后的事实身份保持连续但语义分界。接管资格、用户确认或数值相同都不能把接管前的外部仓位、委托和盈亏改写为 Halpha 入场成交或策略收益；有效接管若在后续形成，必须引用接管时完整账户事实和正式管理责任。旧快照仍可作为明确标时的历史展示，但过期、冲突或格式未知的快照不能支持接管或风险动作。

为账户级系统停止释放提供核对输入时，DAT 只接受服务端在同一环境、场所、账户和统一截止点取得的权威全账户查询事实。覆盖范围必须能够证明账户全部工具的持仓、普通开放订单以及条件或算法开放订单；任一类别、来源、范围、取得时间或新鲜度无法证明时返回未知，浏览器输入、组件缓存、流式估计和不同截止点的拼接不能成为释放证据。完整快照之后出现任何新的账户场所事实，原快照不再足以支持释放，必须重新取得完整快照。DAT 只提供事实，不决定是否释放。

## 4. 消费、修正与恢复

消费者按用途、环境、对象和截止点查询，DAT 返回满足要求的事实或未知原因。缺失、过期、冲突、时钟不可信或归属不明时，不拼接不同截止点、不填零或沿用最近值。

来源修正时追加新事实并引用原因；DAT 不创建修正任务或反向推进计划和动作。系统恢复时，消费者按未闭合责任重新查询；DAT 不拥有系统恢复顺序，也不补发错过动作。

## 5. 组件与验证

量化组件承担订阅、历史读取、工具模型、订单公开事件和连接恢复。Halpha 只保存被实际消费的事实；行情能力不足时优先在当前环境的同一只读连接边界增加窄查询，不建立第二 SDK、缓存或产品侧恢复循环。

同一运行 profile 的历史 K 线、实时报价、实时 K 线及其来源身份必须绑定同一个当前环境。Demo profile 只读取 Demo 端点，Live profile 只读取 Live 端点；当前环境缺失、过期或断连时，对应行情为不可用或未知，不得从另一环境回退、补齐、拼接或沿用缓存。profile 改变时必须关闭旧环境订阅并使旧窗口缓存和序列失效，只有新环境身份与来源已经确认后才能重新提供历史和实时数据。消费者不得把环境或来源身份不匹配的行情用于数量计算、订单预览、场所动作或场所事实。

至少验证来源与时间、幂等和追加修正、未知不被填零、权益字段不由仓位推算、外部身份归属、全仓与逐仓下的激活归因结果一致、多个同向激活的虚拟持仓合计等于交易所净仓、单激活减仓不消耗其他激活持仓、账户级盈亏不被分摊成策略盈亏、资金费按事件时点分摊且精确回总、Demo/Live 隔离、环境切换不保留旧序列、重启后按责任补取，以及只读行情和私有只读账户观察都不能发起交易所变更请求。账户级核对还须验证权益摘要、全部持仓、普通订单和条件或算法订单属于同一账户与截止点，任一查询类别缺失时不保存半快照并保持未知，旧格式不能支持新增风险纪律，快照后的任一账户场所事实使旧快照失效；外部仓位显示和接管资格不能产生虚构入场、策略盈亏或有效管理责任。
