## 1. 模块与所有权

产品按语义分为 planning、capital、venue integration、outcomes 和 user workbench 等模块。每项业务记录只由拥有模块持久化；其他模块调用公开领域能力或读取已提交结果。

模块边界是代码和状态所有权，不要求一一对应进程、服务或数据库。当前模块和物理记录映射由代码与 L4 记录，不作为长期数量上限。

## 2. 运行角色

产品保持交互应用和隔离执行两个逻辑角色。交互角色提供 Web、程序化 API、调用边界、领域请求和查询投影，不创建交易节点或持有真实账户交易凭据；工作台和本机 Monitor 调用同一领域能力。执行角色运行量化组件、发现已启用计划和未决动作，并且是唯一可以发起交易所变更请求的角色。

两个角色通过同一环境的已提交产品记录协作。进程内通知只降低延迟，丢失后能从数据库重新发现；不使用内存队列或同步 RPC 承载唯一业务责任。

角色可以映射为多少进程、实例和操作系统任务属于 L4 产品配置形状；当前本机的实际数量与状态不进入 Git。只要交互角色不能取得真实账户交易凭据或发起交易所变更请求，未来可以按实际问题调整映射。

## 3. 交易上下文与存储

交易上下文由运行环境、场所账户类型和账户身份共同确定。Demo、带单员公域合约账户和个人合约账户复用同一领域与执行逻辑，但分别绑定端点、凭据引用、动作和事实身份；不能把 Live 视为可在多个真实账户间切换的单一运行实例。每个场所账户是独立的运行与执行范围，权威存储使用独立数据库或明确隔离的 schema；具体方式由当前配置决定，不能跨上下文引用、聚合成交责任或默认回退。

Live Read Only 有两个互斥组合。公开前向观察不取得产品数据库写 repository、私有账户凭据或执行客户端，其输出可删除且不能转换为产品事实或动作。私有账户观察取得当前交易上下文精确绑定的只读 API 凭据和 Executor 数据库连接，只能调用账户查询并向 DAT 追加完整账户快照；它不装载执行客户端、EXE 动作 repository、持久动作能力或 Coordinator，不能形成或提交交易所变更请求。配置未同时满足完整凭据对与数据库边界时，不在两种组合间猜测或降级；公开观察与私有账户观察参数同时出现时拒绝启动。两种组合都可以读取账户级系统停止及服务端资格投影，但不能提交释放或其他领域变更。

交互与执行角色的操作系统身份、任务、数据库角色、凭据引用和可写输出按交易上下文与角色分开。App 只取得本上下文的 App 数据库能力和必要的 Web、通知秘密；Executor 只取得本上下文的 Executor 数据库能力，以及当前 profile 明确允许时该精确账户的场所秘密。任一身份、任务参数、数据库、凭据引用或输出目录无法与当前环境、账户类型、账户身份和角色一致对应时拒绝启动，不向另一上下文或角色回退。

运行身份对不可变的运行快照和产品输入只取得读取和执行能力，不取得修改代码、依赖或非秘密配置的能力；需要写入的运行输出限定在自身交易上下文和角色拥有的边界。任一运行角色不得写入另一上下文或另一角色的输出，也不得取得另一上下文的存储连接或秘密。

备份可以作为多个交易上下文共享的辅助设施，但不属于任一上下文的 App 或 Executor，也不随产品组合取得运行权。共享备份身份必须对每个上下文使用独立的只读数据库角色，并把制品写入各自独立的备份目录；它不得取得产品数据库写入、App/Executor 输出、场所客户端、交易秘密或 API Key。不能证明这些边界时停止备份，不扩大辅助身份权限。L4、示例配置与代码只记录逻辑角色和映射形状，当前操作系统身份、目录、数据库实例和任务映射保留在 Git 外。

## 4. 唯一写边界

执行角色只有在 EXE 动作已持久化、CAP 检查当前且交易上下文与条款匹配时，才能调用场所客户端。每个交易上下文在实际传播范围内保持一个写执行者；不同真实账户不得共享互斥锁、写门绑定、未决动作或恢复游标。互斥的当前实现方式由 L4 记录。

正常真实账户增险还要求 Executor 使用写门指纹绑定的同一场所凭据取得当前账户类型事实。带单上下文必须证明当前账户是带单员且目标标的在场所带单白名单；个人上下文必须证明当前账户不是带单员。该事实有界缓存并在增险最终提交边界按时刷新，不能由上下文名称、Key 存放位置或前端选项代替。验证不可用或不一致时失败关闭新增风险；既有激活的撤单、保护、减仓和退出仍按只恢复契约判断。

账户级系统停止释放是交互角色提交的本地产品状态变化，不是交易所变更请求，也不需要向 App 提供交易凭据。CAP 的账户级停止建立、升级、释放和依赖同一停止的动作检查必须在同一账户边界串行化；无法证明当前停止版本和证据仍一致时拒绝释放。

量化组件承担行情、时钟、策略运行、订单对象和公开连接恢复；Halpha 不复制其通用运行能力或建立第二写适配。

## 5. 启动、停止和恢复

启动或非计划恢复按以下顺序：

1. 取得当前运行身份，并确认当前交易上下文只有一个交易所请求执行者；
2. 验证环境、账户类型、账户身份、数据库、迁移和非秘密配置；
   迁移必须保留已有计划、激活、动作和事实；并确认全部未结束激活的冻结快照版本可由当前产品精确读取和验证，不能用当前默认编译器重建；
   生命周期控制入口在启动或重新启用 App、Executor 前必须以受控只读检查核对当前构建支持的唯一 schema 版本；版本不匹配或不可读时拒绝启用任务并返回稳定的数据库就绪原因。该检查不自动执行迁移，迁移仍由显式、串行的维护命令完成；
3. 连接只读场所能力并取得当前账户、订单和持仓事实；正常真实账户增险还须用写门绑定凭据验证当前场所账户类型及带单标的白名单；
4. 让 TRADEPLAN、CAP、EXE 和 DAT 分别检查自己拥有的未闭合状态；
5. 只有所有结果一致且不会补发错过动作时，按运行快照决策依据恢复尚未闭合责任：`STRATEGY_SIGNAL` 重建策略运行，`DIRECT_EXECUTION` 直接从已保存激活、编译快照和事件身份继续，不创建虚构策略。

任一条件未知或冲突时，系统停止受影响新增风险和新的交易所变更请求，只保留查询、已有保护、退出和用户接管。具体未知请求由拥有该动作的领域记录，SYS 不建立恢复状态机。

账户级系统停止跨进程停止和重启保持有效。显式人工释放只改变 CAP 的当前停止版本，SYS 不因此唤醒执行、重建策略、恢复已完成激活或发起交易所变更请求；后续交易必须来自新的有效用户操作和领域责任。没有可按既有激活责任完成用户接管与闭合的外部活动停止保持失败关闭，SYS 不建立账户核对状态机绕过 CAP 的当前支持边界。

正常停止先阻断新动作形成和交易所变更请求，再保存未闭合责任并停止运行组件。数据库不可用时，不以内存继续形成业务记录或发起交易所变更请求。

所有承担产品持续责任或绑定产品监听端口的 Halpha 长期进程都必须进入同一个生命周期控制入口。该入口联合检查操作系统任务、当前仓库及已登记 Git 工作树中的产品进程树和 TCP 监听；能确认属于项目但不能归入受管任务或有效外部登记的长期进程或监听必须显式标为未登记服务，不得静默遗漏。短时构建、测试和迁移命令不因此变成长驻服务。

独立服务不得被产品运行代码按名称、路径、模块或命令行特征引用、导入、启动或停止。独立 Monitor 可以作为本机外部调用者主动调用 App 的通用计划 API；该调用不允许 Trading 引用、探测或管理 Monitor，也不让 Monitor 取得产品数据库、Executor、场所凭据或交易所请求能力，所有持久状态和后续动作仍由 TRADEPLAN、CAP 与 EXE 拥有。独立服务如需进入统一状态视图，只能由服务生产者通过通用外部登记协议主动提交服务标识、PID 和本地 TCP 监听；生命周期入口用操作系统监听实况交叉核验，登记失效或所有权不匹配时显式告警。有效登记只授予状态可见性，不授予产品启停权，也不把独立服务变成产品运行依赖；统一停止必须跳过这些服务。

从命令行特征识别出产品服务名称，只能用于发现未登记产品实例，不能证明该进程由生命周期入口持久管理。没有可核验的操作系统任务时，即使产品服务名称已知且可停止，也必须显示为未登记和仅发现，不能标记为完整受管。

生命周期控制入口主动生成的命令帮助、表头、状态、结果标签和错误前缀只使用 ASCII 英文，避免依赖 Windows 终端的本地编码。路径、配置值、操作系统错误、外部响应或日志等被动透传内容保留来源语言和编码，不要求翻译，也不改变其事实含义。

产品长期进程只能由生命周期控制入口或该入口管理的操作系统任务启动。产品组合启动只包含产品运行角色，不自动启动备份作业或独立服务。停止任务管理的服务时先禁用其自动重启来源，再请求受保护的正常停止；超时默认失败关闭，只有显式强制参数才能转为操作系统强停。停止未登记服务前必须重新确认目标进程仍属于已登记工作树，不能仅凭曾经观察到的 PID 操作；外部主动登记服务由其自身操作入口停止。

进程已经停止只证明对应运行实体不再执行，不证明订单、持仓、保护或其他业务责任已经闭合。需要继续原责任、退出或用户接管时，仍按本节恢复与接管契约判断。

## 6. 复杂度与验证

新增模块、进程、数据库、持久工作或第二操作入口必须由实际并发、隔离、故障或维护问题证明。当前数量不是稳定验收标准。

至少验证状态所有权、数据库事务提交后才发起交易所变更请求、交互角色没有交易所凭据、私有只读账户观察只有 DAT 追加能力且结构上不存在执行客户端与动作能力、Demo 与真实账户隔离、带单账户与个人账户互相隔离、账户类型或带单白名单不一致时失败关闭新增风险、重复与恢复不产生未经 EXE 有界风险控制例外证明的第二动作或任何第二入场动作、唯一 Executor 丢失时禁止新的交易所变更请求、受控启动和重新启用在 schema 版本陈旧或不可读时不触碰任务且状态输出保留稳定原因、项目长期进程和监听不存在未报告的管控外实例，以及停止和两种方向的接管仍可达且不会混淆。账户级系统停止还须验证同账户停止变化与动作检查正确串行化、Live Read Only 无法提交释放或使外部仓位接管生效、重启不会自动释放，以及释放不会启动运行角色或产生交易所变更请求。
