# Halpha 交易计划与启用原则

**文档编号：** HALPHA-TRADEPLAN-001  
**层级：** L2  
**语言版本：** zh-CN  
**上位文档：** HALPHA-CON-001、HALPHA-FLOW-001  
**本文档负责：** 交易计划、固定版本、启用、条件、动作意图、用户控制和结束生命周期  
**本文档不负责：** 经济证据评价、资金计算、事实生产、场所动作执行、页面和当前计划类型

## 1. 唯一职责

TRADEPLAN 把用户已选择的判断、研究结果、Monitor 的明确监控信号、固定决策依据或持仓处置需要变成可理解、可运行、可停止和可结束的交易计划。固定决策依据可以引用产品内固定策略信号，也可以表示用户或 Monitor 已经明确给出的直接执行；普通消息、AI 建议、研究材料和未选择的想法不能直接取得计划效力。

TRADEPLAN 独占计划草案、固定版本、计划启用和运行生命周期。CAP 只检查资金边界；EXE 只处理外部动作；它们不得重新定义计划或启用状态。

## 2. 完整计划与版本

完整计划说明：为什么承担风险；作用对象；决策依据；进入与失效条件；规模、订单分布和期限；动态管理；保护与退出；允许动作；事实未知、失败和用户不可达时的结果。

普通新增风险计划还必须固定一份交易前决策实验记录：本次是盈利导向交易还是机制验证、属于哪一稳定交易形态、可证伪假设、采用证据及其截止点、假设失效与放弃条件和已知局限。直接执行还必须固定一个可复用的交易剧本标识，表示同一套入场、失效、保护和退出规则；规则实质变化时使用新标识，每笔唯一信号身份不能冒充可重复剧本。产品内固定策略继续由策略版本和参数摘要提供规则身份，不另建重复标识。该记录只负责保存决定和比较身份，不取得条件或动作效力；需要自动阻止入场、撤单、保护或退出的边界必须另由类型化计划字段表达。以流程、软件或机制验证为主要目的的计划不得标成盈利导向，后来盈亏也不能反向修改已经固定的目的。

既有外部持仓的减仓或平仓使用独立的“持仓处置计划”。它把一次完整账户快照中的账户、场所、工具、方向、持仓侧、数量和事实截止点固定为不可变基线，只允许在该基线上减少明确数量或归零；它没有 Halpha 入场条件或入场订单计划，不补造 `ENTRY`，激活后直接进入退出生命周期。追加同向仓位不是处置计划能力，必须另建普通新增风险计划并重新通过其交易金额、条件、保护和退出边界；外部基线不因此被改写或扩大。

草案可以不完整和修改，但不能持续值守或产生外部动作。每个计划具有独立于策略定义的用户名称，并保留创建时间和人工、AI 或 Monitor 创建来源；来源只说明创建主体，不产生确认、启用或资金效力。未固定草案可以删除，固定版本及其来源计划不得通过草案删除入口移除。

历史固定计划缺少当前决策实验字段时保持可读并明确为未知，不按名称、盈亏或旧备注补猜交易目的、形态或交易剧本。当前新增风险入口只有在决策实验记录完整，且直接执行已经固定交易剧本标识时才接受计划；持仓处置计划不产生新的市场入场假设，继续使用自身固定处置依据而不伪装成盈利样本。

工作台和程序化接口是同一计划能力的不同入口，不是两套产品模型。对于计划创建、修改、删除、固定、服务端预览、激活和结果查询，两种入口必须使用同一字段范围、类型化 schema、服务端校验、版本与幂等契约、当前事实、CAP/EXE 链路和失败语义；新增计划字段或操作只有在两种入口都可表达和消费时才算完成。页面布局、即时输入提示、浏览器 CSRF 和程序化调用来源标记属于入口差异，不得借此删减或改写计划能力。

Monitor 已经完成入场判断并给出可执行方向时，使用 `DIRECT_EXECUTION` 把信号转换为固定订单计划；信号证据进入决策上下文，稳定信号身份派生各阶段幂等请求身份，另由稳定交易剧本标识说明它采用哪一套可重复规则。前者标识这一笔决定，后者标识跨交易比较规则，两者不得混用。Trading 不复制 Monitor 的监控逻辑，也不把外部监控信号伪装成产品内策略。Research 不调用该入口，只提供由用户或 Monitor 选择后再转换的只读输入。

用户确认后形成不可变版本；会改变资金后果、行动条件、保护、期限或失败处理的修改形成新版本，不能在动作发生后补写旧决定。

产品代码、依赖或数据库版本变化不产生新的计划决定，也不能使已固定计划失去可读性。发布升级必须保留仍在数据库中的固定版本、激活、完整编译快照和动作身份；通过版本化读取器继续验证原内容，或在迁移中保持语义和摘要可核对地转换。运行中的激活继续消费原快照和原动作身份，不按当前编译器重新解释、改价、调量或补发；升级无法证明兼容时阻断发布或新增风险，但仍须保留原责任、保护、退出和接管路径。

## 3. 启用与资金边界

用户通过工作台明确启用一个完整计划，或由其已经配置的 Monitor 对固定版本明确提交一次启用命令，表示允许 Halpha 在该计划绑定的环境、账户、交易金额、动作范围和期限内持续观察并形成动作。创建、修改、固定和预览均不隐含启用；半自动计划的交易金额已经在计划配置中决定，启用只让该固定计划开始运行，不构成第二次资金授权，也不表示已经下单或跳过每次动作的 DAT 事实和 CAP 检查。

启用对象保存或引用所需计划版本、用户决定和交易金额；字段由 L3 统一定义。CAP 消费这些输入并返回检查结果，不拥有启用对象结构或生命周期。

模拟和真实资金必须分别启用，身份和效力不能迁移。

真实账户的盈利导向新增风险计划可以把一份由用户明确选择、面向该账户类型且仍新鲜的 Demo 完全同类证据包作为独立准入前提。该输入只能证明当前计划与某组已冻结 Demo 样本身份相符，不能改写固定计划字段、自动创建真实账户计划、代替用户启用、开放写门或授权资金；验证目的和既有外部持仓处置不以收益证据为前提。服务端在预览和实际启用事务中都必须重新核对，不能由浏览器的通过状态或任意文件选择覆盖。

同一账户与工具可以同时启用多个同向计划；每个启用只拥有自身形成的订单、成交、保护和剩余虚拟持仓。交易所合并净仓不扩大任何计划的作用范围。单向持仓模式下，未闭合反向计划、用户接管范围或无法归属的账户活动会使新的同工具启用失败。

持仓处置计划启用时必须重新读取其原始基线事实和最新完整账户快照。账户、工具、持仓侧、方向、数量、入场价、开放委托或事实截止状态发生变化，或者同范围已有未闭合激活时，旧确认失效且不建立处置激活；页面预览和用户确认都不能覆盖这种变化。

## 4. 条件与动作意图

条件说明观察对象、事实截止点、有效窗口和无法判断时的结果。事实缺失、冲突、过期或连续性不明时，不产生依赖它的新增风险动作。

条件判断形成不可变计划事件和可选动作意图。依赖结构化行情形成入场的策略事件还应保存足以还原本次判断的边界、确认序列、允许偏离、触发参考和事实截止点；只有摘要而没有原始判断值时，后续不得声称能够区分贴近边界的触发与追离入场。策略信号和直接执行只改变入场条件来源，复用相同的计划、事实、CAP、EXE、保护和用户控制边界。重复来源返回原结果；冲突来源保留未知并停止受影响新增风险。动作意图只有经过 CAP 检查并由 EXE 建立唯一动作责任后才可能成为交易所变更请求。

## 5. 停止、退出与接管

用户可以：停止新增风险、要求按计划退出、转入交易场所官方入口接管。三种决定后果不同，使用不同命令；网络超时后查询原请求，不能生成第二决定。

停止新增风险后，同一启用不再恢复新增风险。已有风险继续保护或退出；接管后 Halpha 不再为该启用发起新的交易所变更请求。旧责任闭合后，如需继续交易，用户创建新的启用。

TRADEPLAN 只拥有这些业务决定和生命周期；SYS 拥有系统重启组合，EXE 拥有动作核对。

## 6. 结束

计划只有在能够证明未产生外部变化、全部外部责任已经闭合，或剩余责任明确交给用户时结束。页面提示、进程停止、局部订单终态和持仓显示为零都不能单独证明结束。

详细对象、状态和幂等契约进入 L3；当前计划类型、条件、参数和验证结果进入 L4。
